# Native desktop architecture
SwiftUI provides native navigation, forms, tables, file selection and confirmation sheets. AppKit manages Finder integration, app termination and snapshots of this app's own rendered content. InkKit is the architectural/UX reference; this implementation reuses KOReader Bridge's migration core rather than InkKit's device/configuration logic.
The app starts a bundled pinned Python interpreter using Foundation.Process with an absolute executable path, isolated mode and a minimal environment. A separate helper process handles one allowlisted request; ordinary operations return bounded versioned JSON, while migration streams bounded progress and explicit prompts before a final response. stdout is protocol-only. Diagnostics remove control sequences and common secret tokens. Unexpected failures expose a generic error rather than a traceback.
Operations: health, catalog, details, cleanup_plan, create_demo, execute. Execute maps a typed allowlist to existing CLI arguments and routes core prompts as request-bound replies. There is no arbitrary command, module, code evaluation, file editor or Lua execution API. The helper retains core locks, snapshot verification, fingerprint and compatibility checks, space guards, rollback and exact-restore logic. Defaults are preview-oriented. The GUI requires review before writes and the core still requires final confirmation.
One active operation per app instance prevents conflicting controls. Core project/device locks also coordinate with other app/CLI processes. Stop requests SIGINT for graceful core cancellation/recovery; the app does not force-kill a writing backend. Quit/close is blocked during active work. Ordinary request timeout is 60 seconds, run deadline 24 hours, pending core confirmation 15 minutes. A slow recovery must finish before disconnecting.
Preferences preserve unknown fields; corrupt/future formats are not overwritten. New private host directories use 0700 and files use 0600. Device data stays in the chosen private workspace, never in the application bundle. The build uses an explicit input list and checksum-pinned relocatable CPython; caches, research, device data, real archives and local instructions are excluded.
Synthetic sessions are helper-created private directories marked as samples, with simulated discovery/eject and archive path confinement. They use actual core migration/archive/restore functions and real ditto. Their data and transport do not certify firmware, rendering, fonts or physical hardware.
Developer launch flag --test-root selects isolated preferences. --integration-test exercises actual Swift Process transport, synthetic flows and persistence, then captures the app's own view in light/dark appearance. No screenshot of other windows or private reader data is taken.

Developer screenshots first use a public CoreGraphics own-window capture shim that verifies the window belongs to the current process. It cannot capture other processes. A targeted system-capture fallback and an explicitly flagged NSView fallback exist; incomplete NSView captures must not be presented as complete native screenshots. The CoreGraphics capture API is deprecated on newer SDKs and is used only for development verification, not migration.
