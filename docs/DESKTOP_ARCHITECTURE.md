# Native desktop architecture
SwiftUI provides native navigation, forms, tables, file selection and confirmation sheets. AppKit manages Finder integration, app termination and snapshots of this app's own rendered content. InkKit is the architectural/UX reference; this implementation reuses KOReader Bridge's migration core rather than InkKit's device/configuration logic.
The app starts a bundled pinned Python interpreter using Foundation.Process with an absolute executable path, isolated mode and a minimal environment. A separate helper process handles one allowlisted request; ordinary operations return bounded versioned JSON, while migration streams bounded progress and explicit prompts before a final response. stdout is protocol-only. Diagnostics remove control sequences and common secret tokens. Unexpected failures expose a generic error rather than a traceback.
Operations: health, devices, catalog, details, cleanup_plan, create_demo, execute. Protocol v1 adds optional readerSession and typed workflow readers without changing old callers. New clients receive an array of physical connection choices. bridge_devices.py opens bounded native .kobo/version metadata with no-follow descriptors and maps model codes locally; it queries a bounded/timed macOS IOUSBHostDevice storage subtree, maps BSD device numbers to mounted filesystem device numbers and compares serials only in memory. Shared/unknown product IDs are not guessed as unique models. Native/USB model conflicts require confirmation; unreadable/duplicate identity, ambiguous storage ancestry and mismatched USB serials remain unselectable.
Connection tokens are HMACs keyed by a random per-app-session value over mount, native identity and USB connection metadata. Responses omit raw serials/fingerprints. The app explicitly assigns tokens to roles; reconnecting, remounting or changing metadata invalidates selection/approval. Manual model correction has a native confirmation sheet and execution-time default-No confirmation; it changes a role label, not physical identity. The desktop adapter resolves only current discovered tokens and revalidates at core confirm_device and safe_eject boundaries. Core fingerprint, same-device, locks, capacity, archive/path, compatibility, backup and rollback checks remain. The source is still archived/verified before the target phase; no direct unbacked device-to-device copy is introduced. Sequential CLI behavior and existing run/snapshot schemas are unchanged.
Mount/unmount notifications and a three-second idle refresh update choices; active migrations pause idle discovery. Synthetic sessions use marked isolated directories and an explicit fake USB graph, never the host inventory. Execute maps typed allowlists to existing CLI arguments and narrowly adapts connection selection/presentation; it exposes no arbitrary command, module, code evaluation, file editor or Lua execution. Old clients without readerSession retain the earlier hint-only discovery shape. Defaults are preview-oriented; core confirmations still gate writes.
One active operation per app instance prevents conflicting controls. Core project/device locks also coordinate with other app/CLI processes. Stop requests SIGINT for graceful core cancellation/recovery; the app does not force-kill a writing backend. Quit/close is blocked during active work. Ordinary request timeout is 60 seconds, run deadline 24 hours, pending core confirmation 15 minutes. A slow recovery must finish before disconnecting.
Preferences preserve unknown fields; corrupt/future formats are not overwritten. New private host directories use 0700 and files use 0600. Device data stays in the chosen private workspace, never in the application bundle. The build uses an explicit input list and checksum-pinned relocatable CPython; caches, research, device data, real archives and local instructions are excluded.
Synthetic sessions are helper-created private directories marked as samples, with simulated discovery/eject and archive path confinement. They use actual core migration/archive/restore functions and real ditto. Their data and transport do not certify firmware, rendering, fonts or physical hardware.
Developer launch flag --test-root selects isolated preferences. --integration-test exercises actual Swift Process transport, synthetic flows and persistence, then captures the app's own view in light/dark appearance. No screenshot of other windows or private reader data is taken.

Developer screenshots first use a public CoreGraphics own-window capture shim that verifies the window belongs to the current process. It cannot capture other processes. A targeted system-capture fallback and an explicitly flagged NSView fallback exist; incomplete NSView captures must not be presented as complete native screenshots. The CoreGraphics capture API is deprecated on newer SDKs and is used only for development verification, not migration.

## Per-operation migration review

Protocol v1 accepts optional typed `config.review` only for explicitly bound migration/saved-source workflows: `rolesConfirmed`, `compatible`, `identity` (`preserve`, `new`, `clone`) and `cloneConfirmed`. Boolean values must be actual booleans; unknown fields and invalid choices are refused. The native review binds these choices to this request's physical reader tokens. No consent is persisted in preferences or reused in later requests. FULL/KOREADER writes require compatibility acknowledgement; cloning requires explicit acknowledgement. Preserve falls back to a new identity only when TARGET has none.

The desktop adapter reuses only known start/role/compatibility/identity choices. Role reuse revalidates the bound connection and selected model. It never answers the final migration question, model exceptions, restore, deletion or unrecognized prompts automatically. Verified source/TARGET backups and fresh write-boundary identity checks still run. Read-only connected previews skip the redundant review and compatibility questions. Callers without `review`, including the CLI and sequential desktop mode, retain existing behavior and schemas.

## Native localization

Reviewed `macos/locales/{en,zh-Hant,zh-Hans}.json` catalogs produce standard `.lproj/Localizable.strings` resources during the explicit-input build. The app resolves the chosen bundle directly, so switching Settings → Language updates all four pages and owned sheets without restarting. A locale environment also reaches native SwiftUI controls. Preferences preserve the selection and unknown fields. Core operations receive a fixed locale per request; ongoing output and saved diagnostics are not retroactively translated.

Native labels use explicit catalog keys and named placeholders. Device warning codes and owned helper progress/prompt IDs travel separately from compatible English diagnostics. Cleanup protection uses the core's original structured reason ID. The UI does not infer localization IDs from rendered core text. Machine schemas, model names, user data/paths, old raw reasons and external diagnostics retain their original form. English fallback handles an unsupported locale or missing resource; catalog parity/placeholder checks reject incomplete build inputs.
