# KM-P0-036: Let tests isolate the device-lock directory

## Goal

Device locks live in one fixed per-user directory (`<tempdir>/koreader-migration-locks-<uid>`) shared by every checkout and worktree. Give tests a way to point locks at their own directory so parallel agents' test runs never share lock files, without changing the default location or any lock identity used by real runs.

## Context

- kobo-koreader-migrate.py `DeviceLocks`
- tests/test_entrypoints.py

## Acceptance criteria

- [ ] The default lock directory and lock key derivation are unchanged; existing lock regression tests pass unmodified.
- [ ] Tests that acquire device locks use an isolated directory, and a new test proves two isolated directories do not interact.
- [ ] Any override cannot be used to split locks between two real runs without an explicit, documented test-only path.
- [ ] tickets/README.md Gotchas updated to describe the override.

## Plan

- [ ] Find every test that reaches `DeviceLocks.acquire` without patching `tempfile.gettempdir`.
- [ ] Implement the option chosen under Decisions needed.
- [ ] Add tests and update docs.

## Decisions needed

- Option A (recommended): a test-only hook, for example a module-level setting the tests patch, with no user-facing environment variable. Keeps real-run locking unchanged.
- Option B: an environment variable such as `KOREADER_BRIDGE_LOCK_DIR`. Matches the generic kit pattern but lets two real runs with different environments bypass each other's locks.
- Option C: no change. Lock keys hash the mount path and fixtures use unique temporary mounts, so parallel test runs do not collide today; record that and close the ticket.
